# Cycle: causal J3 action-selection gap audit

Status: artifact-only audit complete; dynamics diagnostic selected

## Decision

Stop the pending four-step geometry-teacher recovery. Existing checkpoints
already show a strong two-step teacher and strong student-versus-oracle
ranking, while task-value information degrades sharply in predicted and
recursively rolled-out states. The next experiment should isolate causal
history and optimization effects on transition fidelity, not increase teacher
lookahead.

## Falsifiable question

Does the causal J3 model trail the matched token policy because its predictor
loses future-relevant information under full-history optimization, rather than
because the two-step geometric teacher ranks actions poorly?

## Evidence audited

The three completed `paper_causal_j3_s{0,1,2}` checkpoints share the same
architecture and protocol and differ only by seed. Planning uses 200 fixed
validation problems per seed. The geometric teacher audit uses 100 anchors per
seed. Representation probes use 13,509 transitions per seed. Uncertainty below
is the sample standard deviation across the three model seeds.

| Measurement | Mean +/- seed SD | Interpretation |
|---|---:|---|
| Strict closed-loop success | .588 +/- .013 | central behavioral gap |
| Two-step teacher top-1 vs symbolic oracle | .890 +/- .036 | privileged diagnostic; teacher is already strong |
| Teacher decisive-pair accuracy | .927 +/- .005 | privileged diagnostic; ordering is strong on covered pairs |
| Student top-1 vs symbolic oracle | .907 +/- .006 | student is not obviously weaker than teacher |
| Student top-1 vs teacher | .863 +/- .025 | some imitation disagreement remains |
| Value from encoded observed state | 1.000 +/- .000 | current state retains the task value |
| Value from one predicted transition | .380 +/- .014 | future-relevant information drops after prediction |
| Value from recursive rollout | .263 +/- .004 | information drops further under rollout |
| State standard deviation | 1.038 +/- .000 | no variance-collapse signal |
| State effective rank | 245.9 +/- .4 | no low-rank-collapse signal |

Teacher top-1 is lower on traces containing distractors
(.851 +/- .055) than on clean traces (.914 +/- .025), but the student remains
strong against the oracle overall. Full strict success is compatible with
compounding per-decision errors over roughly four required actions; the audit
does not support spending the next run on a deeper teacher.

## Validity and limitations

- Teacher-versus-oracle and student-versus-oracle metrics use symbolic oracle
  labels for diagnosis only. They are not proposed supervision or deployable
  evidence.
- All deployed planning results use shuffled current-feasible action menus.
- The available artifacts do not contain the requested action-shuffle
  transition falsifier, selected-action regret, depth strata, or
  objective-specific gradient norms. The diagnosis is therefore directional,
  not a complete causal proof.
- Value-probe degradation measures retained task information, not transition
  identity directly. A matched training intervention is required to test
  whether improving it raises closed-loop success.

## Smallest next test

Keep the flat J3 architecture, objectives, data, seed, shuffled menus, update
budget, and parameter count fixed. Compare sliding causal context windows 1
and 4 with the existing full-history seed-0 reference. Add full-history global
learning rates `1e-4` and `1e-3` around the current `3e-4` setting so a context
result is not confused with optimization scale. Each new cell must emit strict
and slack-2 planning, teacher/student audit, transition and rollout probes,
state variance/effective rank, resolved configuration, and compact summary.

Advance only a cell that improves strict success by at least .05 over matched
seed 0 while preserving teacher quality and non-collapse, or materially
improves one-step/recursive task information with no behavioral regression.
Only the selected cell receives seeds 1 and 2. If no cell passes, retain the
full-history J3 predictor and move to preference/deployment calibration rather
than widening this screen.
